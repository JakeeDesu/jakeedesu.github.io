Privacy Policy

Last updated: October 8, 2026

Projects Overview Staging is a personal project and task tracker for one approved owner. Its staging workspace contains synthetic verification data.

Google sign-in

The application uses Google account identity information, including the account identifier and email address, to authenticate and authorize its approved owner. Google sign-in and the application's authentication provider process this information. Session cookies support sign-in to the private application.

Google Drive permission

A separate backup authorization requests drive.file, Google's per-file Drive permission. The application uses it to create and manage its encrypted backup files in an owner-private folder, download those files to verify recovery, and remove eligible old backup copies under its retention policy. It checks the approved Drive account's email and backup-folder ownership. It does not request permission to read every file in Google Drive.

Storage and recovery

The private application's database and attachment storage are hosted by Supabase, and its application hosting is provided by Vercel. Backup archives contain the workspace snapshot and referenced attachment bytes. Archives are encrypted with age before upload to Google Drive.

The staging backup worker runs in GitHub Actions using protected credentials and protected recovery-key verification access. It downloads, decrypts and restores synthetic backups into an isolated temporary verification target. The original recovery key stays separately held by the owner. Credentials and recovery identities are excluded from downloadable CI artifacts.

Retention

The backup policy retains seven daily copies, four weekly copies and the two latest pre-release copies. Owner-requested and unverified backups are preserved, and the last verified recovery copy is protected. Failed or interrupted recovery material may be kept for investigation and retry. These counts do not promise deletion of every copy after a fixed number of days.

GitHub Actions retains encrypted retry files and sanitized verification reports for 90 days. Temporary recovery verification data is processed in the isolated worker. Existing encrypted Drive copies remain subject to the backup policy and the owner's management.

Use and sharing of Google data

Google data is used for owner authentication and the described backup and recovery functions. It is not sold, used for advertising, or used to train general-purpose AI models. It is processed by the service providers described above only as needed to operate these functions.

Projects Overview Staging's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Revocation, deletion and questions

The owner can revoke the application's access through Google Account connections. Revoking access stops future authorized Drive access; it does not automatically delete application data or existing encrypted backups. The owner manages those records and files separately.

This is a personal application operated by its sole approved owner. That owner manages privacy questions and deletion decisions directly. The application's configured support contact is also shown by Google on its consent screen.

This information site

These public pages contain app descriptions and policies. They do not display workspace records, attachments, backup files or account identifiers. They contain no analytics scripts, forms, sign-in controls or application cookies. GitHub Pages logs visitors' IP addresses for security; see the GitHub Privacy Statement.

Changes

This policy will be updated when the application's data practices change. The date above identifies the current version.
